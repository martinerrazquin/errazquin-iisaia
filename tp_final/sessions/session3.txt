     Plan: Chismoso slides deck (reveal.js, tp_final/slides/)

     Context

     Martin needs a ~5-minute deck to present Chismoso to fellows. It must be
     code that is versioned in this repo: no PDF, pptx or Google. The text is in
     Spanish, with English technical terms where they read cleaner (ciphertext,
     token, hash, fragment…). Agreed choices: reveal.js, custom inline SVG 
     diagrams, directory slides/.

     Hard constraints

     - The codebase stays untouched for the whole workflow. The only files
       created or edited are inside tp_final/slides/. There are no edits to the
       root README.md, the root .gitignore, frontend/, backend/, infra/ or the
       compose files. The root .gitignore already ignores node_modules/ and
       dist/ at any depth, so nothing is needed there.
     - Anything reused from the app (for example the colors in
       frontend/src/index.css) is copied as values into slides/style.css, never
       imported or linked. Changing the look later only means editing slides/.
     - No port clash with the running app. These ports are in use on this
       machine: 3000 (Caddy), 5433 (Postgres), 8080 (Keycloak) and 5173 (Vite
       inside the frontend container). The deck dev server binds to
       127.0.0.1:4300 with strictPort: true in slides/vite.config.js, so it
       fails loudly instead of silently drifting to another port. vite preview
       uses the same fixed port.

     Slides (6)

     1. ¿Qué es Chismoso? A short tagline (central login with Keycloak, but
        secrets still travel in plain chat), then two chat mockups laid out
        horizontally:
        - Left, titled "Hoy" and dimmed in red: A says "pasame la contraseña del
          server X" and B replies "HolaComoEstas2026".
        - A horizontal arrow labeled "Chismoso".
        - Right: the same message from A, and B replies with a Chismoso link
          (https://chismoso…/s#…, shortened).
        - The arrow and the right-hand block appear as a fragment. Text is
          minimal; the idea is that one extra, simple step makes secret sharing
          safe.
     2. Flujo exitoso. One big SVG with actors Emisor (browser), Servidor + DB
        and Receptor (browser), plus Keycloak in a corner. Each step is a <g 
        class="fragment">:
        a. The sender's browser generates an AES-256-GCM key and encrypts
           locally with WebCrypto.
        b. It sends only the ciphertext and the recipients. The server stores
           the ciphertext and SHA-256(token).
        c. A link /s#token.key is produced per recipient. Because token and key
           sit in the fragment, they never reach the server or the logs.
        d. The recipient logs in and clicks "Revelar". The server checks
           identity and token, consumes the grant atomically and returns the
           ciphertext.
        e. The recipient's browser decrypts with the key from the fragment.
     3. ¿Y si…? The same base diagram, dimmed (it is a <symbol> reused with
        <use>), with two red attack overlays as fragments:
        - Someone else uses the URL: they are a non-recipient and get 404, and a
          second use gets 410.
        - Someone steals the DB: they get only the ciphertext and token hashes,
          with no key because the key never left the fragment.
     4. Cómo lo construí. Three cards side by side, each with an inline-SVG
        icon:
        - SPEC: "Una charla LARGA con GPT". Icon: a loop between a user and a
          brain or computer.
        - Implementation: "CC + Superpowers". Icon: one main node fanning out to
          several subagent nodes.
        - UI Restyling: "Ping-pong con CC". Icon: the same loop icon as SPEC, as
          one shared <symbol>.
        - The cards could appear as fragments one after another, or all at once.
     5. Demo. Only the word "Demo", large and centered.
     6. Cierre. "¡Gracias!" in large type, with "¿Preguntas?" on a separate line
        in smaller type.

     Before writing the text for slides 2 and 3, check the flow facts (status
     codes, link format, what the DB stores) against README.md,
     chismoso_spec_v1_1_reconciled.md, backend/app/consume.py and
     backend/app/shares.py. These files are only read, never edited.

     Files (all new, all under slides/)

     - package.json: deps reveal.js@5.1.0 and vite@^8.3.0 (the same major as the
       frontend). Scripts: dev, build and preview.
     - vite.config.js: server: { host: '127.0.0.1', port: 4300, strictPort: true
       }, the same settings for preview, and base: './'.
     - index.html: one <section> per slide, an <aside class="notes"> speaker
       note on each (about 1 minute per slide), and the SVG <symbol> defs (flow
       base, loop icon, subagents icon).
     - main.js: imports reveal.js, its CSS and the RevealNotes plugin, then
       calls Reveal.initialize({ hash: true, slideNumber: true, width: 1280, 
       height: 720 }).
     - style.css: the custom theme built on CSS tokens, chat bubble styles,
       diagram styles (actors, arrows, ciphertext vs plaintext, red for attacks)
       and the card layout.
     - README.md: cd slides && npm install && npm run dev, which serves
       http://127.0.0.1:4300. Also covers S for the speaker view and F for
       fullscreen.

     Verification

     - git status shows only slides/ as new: no modified tracked files and
       nothing outside slides/.
     - npm install && npm run dev serves on 4300 while the app stack keeps
       answering on 3000.
     - A Playwright or browser screenshot of every slide and fragment state at
       1280×720 and 1920×1080 shows no overflow and readable diagrams.
     - Pressing S opens the speaker notes, and npm run build succeeds.
     - Martin reviews the Spanish copy. Commit only when asked.

  1. Repo layout and infrastructure

  - Proxy: Caddy on plain http://, published on 127.0.0.1:3000 and [::1]:3000.
    On this machine app.localhost resolves to ::1. It sends /api/* to FastAPI
    without stripping the prefix, and everything else to Vite (WebSocket upgrade
    included for hot reload) or to the static bundle in production mode. Both
    stacks use port 3000 because that's the only origin Keycloak allows, so you
    run one stack at a time.
  - Database: postgres:18-alpine, published on 127.0.0.1:5433. An init script
    creates chismoso and chismoso_test.
  - Keycloak connection: the backend joins the external network
    ${IDP_DOCKER_NETWORK:-chismoso-idp_default}. Dev .env sets OIDC_JWKS_URL=htt
    p://keycloak:8080/realms/chismoso/protocol/openid-connect/certs. The iss
    check always uses OIDC_ISSUER. I'm not using the alternative, a Caddy alias
    that pretends to be idp.localhost, because it adds moving parts.
  - Environment variables: a single .env file. Compose maps MAX_PLAINTEXT_BYTES
    to VITE_MAX_PLAINTEXT_BYTES, and likewise VITE_OIDC_ISSUER and
    VITE_OIDC_CLIENT_ID. Dev passes them as environment variables; production
    passes them as build arguments.
  - Security headers: the production Caddyfile sends the strict headers from §27
    exactly. The dev one relaxes the policy only for Vite: inline React refresh
    code and its own WebSocket, never third-party code.

  2. Backend (FastAPI, synchronous)

  - Modules:
    - config (pydantic-settings)
    - db, models, Alembic migration 0001
    - auth: PyJWT plus a cached PyJWKClient; checks signature, iss, exp/nbf,
      that chismoso-api is in aud, and resource_access.chismoso.roles for admins
    - usernames: strip, lowercase, reject any @, then match
      ^[a-z0-9][a-z0-9._-]{0,63}$
    - encoding: base64url without padding, with a length check before decoding
    - errors: one error format for everything, including FastAPI's validation
      errors, without echoing submitted values
    - shares, consume, admin: route plus logic, following §12.2 closely
  - Consume: a badly formed token returns the generic 404. The token hash is
    SHA-256 of the 32 decoded bytes.
  - Creation times: now() inside the transaction, and expires_at = now() + 
    make_interval(mins => n).
  - Logging: uvicorn's access log is off. My own middleware logs method, route
    template, status and latency. Every API response gets no-store, nosniff and
    no-referrer. Caddy caps request bodies on /api.

  3. Frontend (React, TypeScript, Vite, react-router)

  - Routes: / create, /s consume, /admin, and /auth/callback. The callback page
    only runs signinPopupCallback and renders nothing else.
  - Login: oidc-client-ts with in-memory user and state stores, popup login
    everywhere, scope openid, no silent renew, no refresh tokens. Reloading the
    page means logging in again; Keycloak's own session cookie makes that a
    one-click popup. A 401 asks you to log in again and never retries a consume
    on its own.
  - Code units:
    - crypto/v1.ts: pure WebCrypto functions
    - link.ts: builds and parses the #v=1&t=…&k=… fragment
    - api.ts
    - i18n/errors.ts: maps error codes to Spanish messages
  - Pages: basic and functional, with plain CSS for now. The consume page has
    explicit states:
    - insecure browser context
    - malformed link
    - login needed
    - ready (warning plus button)
    - consuming
    - revealed
    - decryption failed after consume
    - error
  - Later: after everything works end to end, a separate UI polish pass,
    possibly with shadcn/Tailwind. That pass has to check the strict CSP,
    because Radix sets inline style= attributes.

  4. Testing and build order

  - Backend: pytest against chismoso_test on port 5433, with migrations applied.
    Tests sign their own JWTs with an RSA key and a stub key set, so most tests
    don't need Keycloak. They cover:
    - concurrency, using threads with separate sessions: exactly one successful
      same-grant consume, and both shared-token grants succeeding
    - a simulated cleanup transaction locking Share then Grant, to check for

    - captured logs, checked for leaked secrets
  - Known crypto test vectors: a Python script using cryptography generates

    cross-check between two implementations.
  - Frontend unit tests: Vitest for crypto, links, error mapping and
    consume-page logic, with the API mocked. They cover: a malformed fragment
    never calls consume, the callback never consumes, and a wrong key shows the
    "already consumed" message.
  - End-to-end: Playwright against http://app.localhost:3000 with real Keycloak
    popups.
    - Main flow: aperez creates a share for bgonzalez and csaul, each consumes

    - Admin: flapinto sees the admin list; others get 403.

  - Build order for the plan:
    a. scaffold, infrastructure and database

  ### Important (should fix before merge)

  **1. The dev backend runs without `--no-access-log` and without `--reload`**
  (`tp_final/compose.yaml:21-24`; this bug comes from the plan itself, around
  line 3062).
  - **What's wrong:** `command: >` is a YAML folded scalar. Lines that are
  indented more than the first keep their newlines, so the `sh -c` script ends
  the uvicorn command at the newline after `--port 8000`.
  - **Evidence:**
    - `docker top chismoso-backend-1` shows the process as `uvicorn
  app.main:create_app --factory --host 0.0.0.0 --port 8000`, with no further
  flags.
    - The backend logs contain uvicorn access lines such as `INFO:
  172.24.0.5:41706 - "GET /api/v1/admin/shares HTTP/1.1" 401`.
    - The startup log never says it is watching for changes.
  - **Why it matters:**
    - It contradicts design §4 ("uvicorn's built-in access log is disabled") and
  spec §22/§28, which allow logging route templates only, never complete URLs.
    - A client that wrongly puts a token in a query string would have it logged
  in full.
    - The README's "backend (--reload)" is false; backend hot reload silently
  doesn't work.
    - Prod is not affected: the Dockerfile CMD is a single line.
    - No test caught it, because the backend tests run the app in-process.
  - **Fix:** use the YAML list form, put the command on one line, or use `|`
  with `\` line continuations. Then check with `docker top` that the flags are
  there.

  **2. A label containing a lone UTF-16 surrogate returns 500 instead of 422**
  (`tp_final/backend/app/shares.py:91-95`).
  - **Evidence:** I checked this with a small script. A JSON label containing
  `"x\ud800y"` passes `StrictStr` validation, and psycopg's string encoder then
  raises `UnicodeEncodeError: surrogates not allowed`. In the app, that error
  reaches the middleware and becomes a 500 `internal_error`.
  - **Why it matters:** Review Focus #4 names exactly this kind of input (input
  that breaks the Postgres types must give 422, never 500). A browser can send
  it: `JSON.stringify` writes lone surrogates out as `\ud800`.
  - **Fix:** next to the NUL check, reject labels that can't be encoded as UTF-8
  (`try: label.encode("utf-8") except UnicodeEncodeError: raise
  invalid_request(...)`), and add a test case. Recipients and base64 fields are
  already safe because their regexes reject such characters.

  **3. Pasting a second link into an open `/s` tab keeps the old link's state**
  (`tp_final/frontend/src/pages/open/OpenPage.tsx:28` with
  `tp_final/frontend/src/App.tsx:23`).
  - **What's wrong:** the link is parsed only once, in the `useState`
  initializer. When the new URL differs only in its fragment, the browser
  updates the page in place without reloading. The `<OpenPage/>` element stays
  mounted, so its state is kept.
  - **Effect:** suppose the recipient has link A open and pastes link B into the
  same tab.
    - If A was already revealed, A's plaintext stays on screen while the address
  bar shows B.
    - If A was not yet revealed, clicking "Revelar secreto" spends A's one-time
  grant while the user believes they opened B.
  - **Why it matters:** a recipient who gets several links from the same sender
  can easily do this. The result is a misattributed secret and a confusing "ya
  fue obtenido" later on A. It does not leak anything to another user.
  - **Fix:** either remount on hash change (wrap the route as `<OpenPage
  key={useLocation().hash} />`), or listen for `hashchange` to re-parse and
  reset the page state. Add a unit test.

  ### Minor (acceptable to leave; listed for follow-up)
  1. **Admin page size can break the admin page** (`backend/app/admin.py:56-59`,

# Prompts TP 1

## 1) Prompt inicial

```
TASK: Implement a single-HTML-file "Weirdle" (a variant of the Wordle game with some added annoying components). 

HIGH LEVEL STRUCTURE:
* Prefer semantic HTML (header, main, section, article, nav, footer, aside) instead of a div soup. Doesn't mean to not use div, but use them sparingly.
* Typical wordle structure: title with "Weirdle", main body with the 5-letter and 6-chances, below that there's the keyboard. There will be a "Select letter" button below the keyboard. A nav to the right for configuring some aspects of the game that we will cover afterwards.
* Annoying variation 1: The usual wordle game has a virtual keyboard + submit + backspace. Some also support physical, direct keyboard input. Weirdle disallows direct input, and also the virtual keyboard is "read-only". Instead of clicking the desire letter, there's a clickable button below the keyboard that says "Select letter". At each time there's one highlighted letter, clicking on said button inputs that letter. After LETTER_JUMP_MS (variable, measured in milliseconds, default 750) the highlighting jumps to a random different letter. There is also no submit button. Instead, when the fifth letter is selected, the word is automatically submitted. If it's not a valid word, the row is wiped.
* Annoying variation 2: When a valid word is submitted, wordle shows letters in green for correct-letter, correct-placement matches, yellow for correct-letter but wrong-placement partial matches and gray for incorrect letters. This does so too but after SHOW_HINT_MS (variable, measured in milliseconds, default 1500) the hints dissapear.
* The nav bar will support configuration options. For each option, there should be a text and the way of configuring it (can be a checkbox, a slider, etc.). Right after the text and before the way of configuring it (which may be below or to the right depending on its size), there should be a help icon that shows an explanatory text upon hovering. Rough example: "Enable hard mode (?)  [X]" and the (?) represents the usual circle with a "?" inside. When hovering it, it shows a text box explaining what hard mode is.
  * Option 1: Switch speed
    * Help: "Control how fast the letter switches to another. Measured in milliseconds".
    * Configuration way: slider. Min = 100, Max = 2000. Default = 750 (as stated before)
  * Option 2: Hint delay
    * Help: "Control how long the color hints last on a submitted valid word. Measured in milliseconds."
    * Configuration way: slider. Min = 200, Max = 2000. Default = 1500 (as stated before).
  * Option 3: Loser mode
    * Help: "Easier mode for losers. Used, incorrect letters are skipped while jumping".
    * Configuration way: checkbox. Default: unticked.
  * Base of the nav bar: new game
    * Note: it's the button for resetting the game. Wipes all rows, re-samples the secret word.

IMPLEMENTATION DETAILS:
* Base yourself on the "usual" UI of famous Wordle implementations' look & feel.
* Support dark and light modes. The button for changing this should be at the bottom left. 
* Use sans-serif font family.
* Use a simple, hardcoded 50-word or so list for valid words.
* Each new game selects the secret word at random from the list of valid words.
* You can implement partial functions and drafts, but the end result must be a single HTML file with the HTML base + CSS + vanilla JavaScript.
* "Loser mode" works by saving the used, wrong letters from previous rows. When enabled, the available pool of next jumpable letters are the standard pool but the used wrong ones are substracted. This is a "backend" only option, it provides no visual difference as there's no need to gray out the wrong ones like in usual wordle. ONLY changes the pool of pool of options for next letter, no visual difference.
```

**Qué intentaba lograr:** un one-shot del juego. En algunos lugares fui un poco vago porque como el juego es famoso, había más chances de que el resultado fuera superador en áreas como el styling al decirle cosas como *Base yourself on the "usual" UI of famous Wordle implementations* que intentando especificárselas por mi cuenta. Similar a los ejemplos brindados en clase y en el repositorio, se dividió el prompt por sectores de detalle creciente. En este caso fue tarea -> estructura -> detalles de implementación. Se utilizó como limitación base una lista de aproximadamente 50 palabras para no incurrir en *bloating* del contexto debido a una lista extensa.

**Qué devolvió:** un juego sólido, funcional. Se observaron 2 bugs, uno visual y uno de funcionamiento. El visual es que en pantalla completa en un navegador, el juego no toma todo el ancho de la pantalla. El de funcionamiento es que la lista de palabras incluye "ISLAND" que no tiene 5 letras.

**Cómo seguir:** como se presume que, de los 2 bugs, el más propenso a introducir un error por inflar el contexto es el de la lista de palabras, primero se arregla el visual.
